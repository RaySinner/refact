# v8.7.4

v8.7.4 extends the standard model-slot set to every subagent: any subagent can now be pinned to `model_2` or `task_planner` from configuration or call arguments, and the GUI subagent editor exposes all six standard slots in a dropdown.

## Highlights

- **All six standard model slots work in every subagent** — `default`, `light`, `thinking`, `buddy`, `model_2`, and `task_planner` can be selected in subagent YAML (`subchat.model_type`) or passed in tool-call arguments. Previously only the first four were wired end to end.
- **Model resolution is explicit and layered** — A subagent call resolves its model as: call-argument `model_name` → call-argument `model_type` → configured `subchat.model` → configured `subchat.model_type` → parent model. An unresolvable configured model type returns an error instead of panicking.
- **`model_2` and `task_planner` slots added to `ChatModelType`** — `model_2` maps to the `chat_model_2` default and `task_planner` maps to the `task_planner_agent_model` default, so planner-style subagents can run on a dedicated planner model.
- **GUI subagent form now uses a model-slot dropdown** — `SubagentForm` replaces the free-text `subchat.model_type` field with a select covering all six standard slots, preventing typo'd slot names in saved subagent configs.
- **Customization registry validation extended** — The subagent config validator now accepts `model_2` and `task_planner` as valid optional `subchat` params, so configs using the new slots no longer trip validation.

## Behaviour changes

- **Subagent model resolution order is documented and enforced.** When a subagent is invoked, its model is resolved from the call arguments first, then the subagent's own configuration, then the parent model. A configured `subchat.model_type` that is not one of the six standard slots is rejected with an error return rather than an `unreachable!` panic.
- **`model_2` and `task_planner` are now first-class `ChatModelType` values.** The engine accepts these serde names (`model_2`, `task_planner`) wherever a model type is resolved, and maps them to the corresponding capability defaults.

## Subagents and customization

- `subchat.model_type` in a subagent YAML or project `.refact/subagents/*.yaml` may now be `model_2` or `task_planner` in addition to the existing `default`, `light`, `thinking`, and `buddy`.
- The GUI Customization subagent editor presents `subchat.model_type` as a select with all six standard slots.
- The customization-registry subagent validation accepts the two new slots as valid optional `subchat` params.
